## С чего начать

1. Прочитай этот файл и конкретное задание пользователя. Если задача ещё не дана, зафиксируй готовность и запроси её; не начинай произвольный редизайн.
2. Проверь распаковку: `python3 tools/verify_package.py`. Проверка SHA относится к исходному срезу до твоих изменений; после редактирования отличия ожидаемы.
3. Выбери ровно один целевой вариант по заданию. Прочитай корневой AGENTS.md, AGENTS/README/DECISIONS выбранной папки и нужные разделы паспорта. Не нужно загружать в контекст все машинные журналы и старую хронологию.
4. Ориентируйся на текущие файлы. Если README старой задачи пишет «ожидается пилот», актуальные результаты — LAB-015. Будущие концепции и примеры исследования отделены от реализованного кода.
5. Выполни ясное поручение в его области, проверь изменение и верни результат по 02_VALIDATION_AND_RETURN.md. Доступ к исходному GitHub для этого пакета не требуется.

## Запуск

Самим приложениям не нужны сборщик или backend. Из корня распаковки запусти:

```sh
python3 -m http.server 8041 --bind 127.0.0.1
```

Открой нужный путь: `/personal/`, `/personal-lab/`, `/personal-lab/experiments/flexible-complexity/`, `/personal-lab/experiments/ai-strategy/`, `/next/` или `/`. Браузер должен быть на той же машине либо использовать доступную ему тестовую среду. ES-модули/PWA требуют HTTP(S), не file://. Занятый порт замени на свободный; чужие процессы не завершай. Основная Personal/лаборатория используют локальные шрифты; старые root/демо могут обращаться к внешним оформительским ресурсам.

Личные данные отсутствуют. Для автоматизации используй временные контексты и вымышленные данные с блокировкой внешней сети. Пакет не даёт доступа к аккаунтам, GitHub, платным API или работающей среде координатора. Новое ясное задание выполняй без повторных разрешений на рутинные локальные шаги; не приписывай себе недоступные запуски/публикации.
