Service worker регистрируется в своей папке. Реальные данные из `personal/` автоматически не читаются и не переносятся. Формат ручного JSON-экспорта пока сохранён (`personal-1`, модель v2); совместимость будущих изменений нужно проверять отдельно.

## Как выполняем каждую следующую задачу

1. Формулируем небольшую задачу и ожидаемое поведение. Предложение или обсуждение остаётся предложением до поручения на реализацию. Новые функции сейчас ещё не выбраны.
2. Помощник сверяет статус, код и изменения Git. По умолчанию меняет `personal-lab/`, не переносит туда параллельные изменения вслепую и не трогает пользовательские сохранения.
3. Заводит запись **LAB-001, LAB-002…** в CHANGELOG: просьба пользователя, исходное состояние/коммит, что меняется и почему, затронутые файлы, влияние на данные, проверки, ограничения. Для изменения HTML сначала делает проверенную побайтовую резервную копию по корневым правилам.
4. Реализует только порученную задачу, выполняет подходящие проверки на вымышленных данных. После изменения ресурсов повышает версию кэша лаборатории. Обновляет запись результатами и краткий текущий статус.
5. Отдельно фиксирует: реализовано; проверено помощником; принято пользователем; сохранено локальным Git-коммитом; отправлено в репозиторий; опубликовано; перенесено в Personal. Один статус не заменяет остальные. В журнале указывает SHA коммита, когда он известен; собственный SHA текущего коммита можно найти через историю файла.

При публикации лаборатории обновляется её путь; принятие правки в лаборатории само по себе не означает её перенос в основную Personal. Существующий порядок Git/Pages задан корневым AGENTS.md. При изменении только документов публикация приложения не запускается.

## Переход на другой аккаунт

Правила распределения задач между моделями и экономии лимита относятся только к лаборатории: [personal-lab/AGENTS.md](../personal-lab/AGENTS.md), [шаблон задания](../personal-lab/TASK_TEMPLATE.md). Их принятие не меняет порядок работы основной модели над Personal.

Смена аккаунта ChatGPT сама по себе не требует менять код приложения. Другой помощник может продолжать ту же папку `personal-lab/`, если его аккаунт имеет доступ к этому репозиторию и получает нужный коммит. Сам аккаунт не переносит локальные файлы текущей машины.

Перед переходом помощник составляет короткую запись в CHANGELOG: последний завершённый LAB, незавершённые действия, проверки, вопросы, точный коммит и состояние отправки/публикации. Изменения, которые должны попасть в другой checkout, нужно сохранить в Git и отправить в доступную ветку по действующему порядку; локальный коммит без отправки другому аккаунту ещё недоступен. Полный ZIP — только по отдельной просьбе. По завершении LAB-000 файлы подготовлены локально, отправка в Git и публикация не выполнялись.

В новом чате можно передать такой текст:

Прочитай `AGENTS.md`, `LifeGame_CURRENT_WORK.md`, `docs/DEVELOPMENT_HANDOFF.md`, `personal-lab/AGENTS.md`, `personal-lab/CHANGELOG.md` и `personal-lab/BASELINE.json`. Сверь HEAD, рабочие изменения и последние записи. Продолжай с последней незавершённой задачи; перенос в `personal/` не подразумевается. Задача: …

Приватная переписка не копируется помощником и не помещается в публичный репозиторий. Этот документ фиксирует рабочие решения и проверяемые факты; полного содержания прежних разговоров он не восстанавливает. Сохранения приложения относятся к браузеру и адресу, не к аккаунту ChatGPT/GitHub; их передача — отдельный пользовательский JSON, когда она потребуется.

## Сообщение основному оркестратору

**Для главной модели, с которой создавалось приложение:** в отдельном чате пользователь организовал лабораторию `personal-lab/` на базе Personal 1.2.0, коммит `90df9542bbffa5651fd31bdad12460a4c586c3ef`. У помощника этого чата ограничен лимит, поэтому для лаборатории согласованы координация внешних моделей пользователя, задания по ролям и Arena-батлы по необходимости. **Эти ресурсные и организационные правила действуют только для лаборатории. Они не изменяют твой порядок работы над основной Personal и не предписывают тебе делегировать её задачи.**

При возвращении пользователя сначала прочитай журнал лаборатории и сверь фактический Git. Можно продолжить лабораторию либо по отдельному поручению перенести выбранные улучшения в Personal. При переносе используй журнал и исходные хеши, проверь результат и сохрани изменения, сделанные в основном проекте параллельно. Принимать копию целиком или считать все предложения моделей согласованными не требуется.

## Если захотим перенести улучшения в основную Personal

Это отдельное поручение с перечнем выбранных LAB-записей. Перед переносом сравниваем три состояния: Personal из исходного коммита BASELINE, актуальную `personal/` и актуальную `personal-lab/`. Проверяем, не изменял ли основную версию другой аккаунт. Переносим выбранные правки по файлам и сценариям, разрешаем конфликты, сохраняем production-имена ключей и кэша. Копировать всю папку лаборатории поверх основной нельзя: так можно затереть чужую работу и перенести лабораторные имена хранилища.

После переноса проверяем затронутые сценарии и сохранения, фиксируем соответствие LAB → коммит основной версии → публикация. Откат кода не должен автоматически откатывать или очищать пользовательские данные. Пока такого переноса нет.

## Воспроизведение

Из корня checkout `/workspace/life-game`:

```sh
python3 -m http.server 8041 --bind 127.0.0.1
```

Процесс оставляем в отдельной сессии. Внутренний путь лаборатории — `/personal-lab/`. Проверка HTTP: `curl -fsS http://127.0.0.1:8041/personal-lab/`. После восстановления облачной машины сервер нужно запускать заново. Приложению не нужны сборка, backend, секреты или установка npm-пакетов.

Проверки из корня выполнять последовательно; `browser.py` создаёт игнорируемый каталог отчётов:

```sh
python3 personal-lab/tests/browser.py
python3 personal-lab/tests/update-live.py
python3 personal-lab/tests/locations-live.py
python3 personal-lab/tests/offline.py
python3 personal-lab/tests/isolation.py
```

Нужны Python Playwright и `/usr/bin/chromium`. Все контексты временные, данные вымышленные, внешние запросы блокируются. `offline.py` и `isolation.py` запускают собственные временные серверы. Физическая приёмка телефона и Safari остаётся отдельной. Актуальные результаты — в CHANGELOG, подробные JSON — в игнорируемом `personal-lab/verification/`.
