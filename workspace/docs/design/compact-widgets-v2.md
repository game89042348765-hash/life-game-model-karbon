# Оформление виджетов: три варианта на прежнем демо

[Открыть образец](https://game89042348765-hash.github.io/life-game/demo/compact-widgets-v2.html) · [Первое демо](https://game89042348765-hash.github.io/life-game/demo/compact-widgets.html)

7 ноября 2026 года. Пользователю нравится компактный подход, но не внешний вид. Последнее уточнение: функционал сохранять, работать именно над оформлением; приложенный скрин служит пояснением, не образцом для копирования.

## Область изменений

Одинаковые исходные Шаг к цели/Посильный план/Ритм недели, прежние кнопки и поведение. Главный script скопирован из первого демо без единого изменения. CSS меняет поверхности, палитру, границы, скругления, шрифтовую иерархию, глубину и оформление существующих элементов. Дополнительный изолированный script переключает только оформление и поясняющую подпись. Он не обращается к состоянию виджетов и не записывает настройки.

1. Графит: нейтральные тёмные поверхности, спокойные границы, мягкая глубина.
2. Тёплый: оливковый оттенок поверхностей, тёплые блики, золотые числовые акценты.
3. Контур: более чёткие линии, небольшие скругления, графичная типографика.

Панели получают те же цвета и границы. Переключение не сбрасывает выбранное дело, план, таймер и факты. Данные вымышленные, только в памяти; reset/reload возвращают исходный пример. Прогресс основного приложения не читается и не записывается. Новый состав действий, перенос выполнения на карточку и другой сценарий таймера сюда не входят.

## Проверки

Побайтовая сверка главного script с первым демо; node --check обоих script. Изолированный Chromium с блокировкой внешних запросов: прежние сценарии плана/таймера/времени/отмены, оценки/ноль/неизвестность/облегчение/возврат, ориентир/отдых/факты; три оформления на восьми ширинах 320–1440 px, панели, клавиатура и Escape, сохранение содержимого и паузы при смене оформления, reset/reload. Ошибок JS нет; прогресс и ключи хранилища не изменяются. Safari/iOS и ручная приёмка отдельно.

Основной index.html, первый образец и существующий ZIP не изменены. Следующий шаг — выбрать/уточнить оформление, затем отдельно перенести принятую визуальную систему, сохраняя действующий функционал.
