# Стратегия — первая рабочая версия

7 ноября 2026. Реализовано по просьбе пользователя после [разбора концепции](strategy-analysis-2026-11-07.md). Это часть текущего LifeGame, не автономная демонстрация.

> Статус UX: пользователь отклонил эту компоновку на телефоне. Ниже описано существующее поведение, а не принятый интерфейс. Для нового выбора подготовлены [три мобильных демо](strategy-mobile-demos.md).

## Вход и ежедневное использование

Главная → Мои виджеты → Стратегия → Открыть стратегию. Системный виджет можно убрать, вернуть из каталога и включить в Конструкторе. Пятой нижней вкладки нет.

Обзор показывает реальные сферы, включая отдельную виртуальную группу Входящих при наличии заданий. Выбор сферы раскрывает её смысл, цели, дела и наброски. Поиск доступен по всем объектам; есть текстовый список элементов карты. Перемещение холста, увеличение кнопками/колесом/двумя пальцами меняют только вид, не позиции или связи в данных.

«Что делать сейчас» показывает доступные реальные незавершённые дела и будущие элементы, которые можно взять в работу. В локальном «Пути» показываются оставшиеся обязательства выбранной ветки и связанные дела реальной цели. Смысл и причина не выдаются как исполняемые шаги.

Выполненная часть по умолчанию скрыта; «Показать выполненное» раскрывает историю. Раскладка видимого графа строится заново после фильтрации, история не добавляет глубину к оставшимся условиям. Принадлежность к сфере и зависимости из других сфер различаются: выбор сферы не обходит чужие зависимости для удаления/скрытия соседней ветки. «Я сейчас» — визуальный якорь, а не новая запись выполнения.

## Данные

- Исходные задания/цели/блоки и их история остаются в прежних коллекциях state. Проекция не хранит независимых копий названий/статусов реальных объектов.
- Основной JSON пополнился strategy: `{version:1,drafts:[],links:[]}`. Старое отсутствие поля даёт пустую стратегию. Оболочка общего экспорта LifeGame остаётся version=1.
- Черновик: `{id,kind,name,description,blockId,reqMode,actual}`. kind: cause/meaning/goal/task; name 1–120, description ≤2000, blockId строка либо null, reqMode all/any, actual null либо `{kind:"goal"|"task",id}`. Существующий block.meaning не мигрирует в массив; дополнительные смыслы относятся к стратегии.
- Ссылка: `{id,from,to,kind}`. from/to — ключи `block:<id>`, `meaning:<blockId>`, `goal:<id>`, `task:<id>`, `draft:<id>`. kind related/helpful/required.
- После включения черновика в работу его ключ draft остаётся стабильным, но имя, статус и сфера читаются из созданной реальной записи. Обычный реальный узел с тем же ID второй раз не рисуется. Все прежние линии сохраняются.
- Проверяются структура, версия, длины, уникальность ID/пар ссылок, существование ссылок на черновики, уникальность actual и циклы обязательных условий, включая алиасы реальных объектов. Ограничения первой версии: 2000 черновиков, 10000 линий. Реальные архивные/потерянные ссылки обозначаются явно; импорт истории не требует выдуманного восстановления объектов.
- UI-key lifegame-strategy-view-v1 хранит только выбранный ключ/режим/показ выполненного. Поиск и камера в памяти. Ничего из этого не выполняет дело и не меняет деньги.
- widgets v8 → v9 однократно добавляет strategy в начало Моих виджетов с showInDay=false. В v9 удалённый виджет сам не возвращается. Существующие размещения/избранное сохраняются.
- Новая JSON-копия с widgets v9 требует обновлённого приложения. Старые JSON-копии поддерживаются новым кодом. Для локального использования вместе с HTML нужны assets/strategy.js и assets/strategy.css.

## Связи, условия и история

Связано/Помогает не блокируют. Принадлежность строится из block/goalId и не переписывается от рисования линии.

Обязательное условие направлено от достигнутой цели или разового дела к будущему делу/цели. Для all нужны все факты, для any достаточно одного. В удовлетворённой альтернативе второй вариант не объявляется обязательным следующим шагом. Циклы запрещены.

Повторяемое дело отображает выполнение сегодня и не может быть новым постоянным условием. Если расписание уже связанного реального задания изменено на повторяемое, обычный редактор не блокируется; такое условие перестаёт считаться постоянным фактом. Серии и числовые условия привычек не введены.

Завершённая цель может удовлетворять условие по своему историческому факту, даже если её сфера в архиве. Если объект исчез и нет достоверного факта, условие не выдумывается. При отмене выполнения доступность будущего пересчитывается. Уже взятые в работу реальные дела/цели не исчезают и не блокируются: карточка предупреждает, что условие изменилось.

## Безопасные изменения

Обычная правка карты идёт через widgetChange/transact без начисления бонуса, с прежними snapshot/quota-защитами. Ошибка записи не меняет подтверждённое состояние; окно сохраняет введённый текст. Изменение графа в другой вкладке отклоняет устаревшее сохранение формы.

Взять в работу — отдельная форма с названием, сферой, наградой и необязательной явной целью для дела. Создание реального объекта и сохранение actual выполняются одной транзакцией, с повторной проверкой условий/даты/текущего графа. Повторное нажатие не создаёт дубль. Выплат за открытие/создание ветки нет. В план дня автоматически ничего не добавляется.

«На сегодня» не начисляет награду. «Начать 2 минуты» вызывает штатный startTaskFocus для уже запланированного дела. Выполнение/отмена дела и достижение/отмена цели вызывают прежние обработчики и подтверждения с защитой баланса. «Добавить дело к цели» открывает прежнюю форму с явным goalId. Обычное редактирование вне карты сразу отражается в проекции.

Удалить можно только неактивированный набросок и его линии, после пояснения последствий. Другие узлы остаются. Отмена правки карты хранит до 25 снимков графа в памяти; она не отменяет реальные выполнения, награды или активацию. При внешнем изменении графа старую отмену применять нельзя.

Новые AI-права, внешние API, новые награды и штрафы не добавлены. Квесты/бонусы/календарь продолжают работать на своих экранах; автоматического приписывания их сферам нет. Перенос их на карту — дальнейшее развитие.

## Проверки

На изолированных вымышленных данных, внешние запросы блокированы:

- чистая модель: старое отсутствие strategy, all/any, конкретные действия, история/архив, уникальность реального объекта, некорректные данные/циклы/алиасы; 1000 узлов обязательной цепи без переполнения стека;
- Chromium: переход из системного виджета, отсутствие записи от просмотра, настоящий клик по SVG, 320/390/768 px, создание наброска/условия/пути, реальное выполнение, включение будущего без выплаты, явный goalId, план и штатный таймер, reload, отмена только графа;
- обычные экспорт/импорт LifeGame, старый JSON, 5 некорректных импортов без изменения данных, quota failure с сохранением текста формы, конфликт двух вкладок, удаление виджета в v9 без возврата;
- 50 выполненных этапов: компактный путь и полная история, any с уже выполненной альтернативой, двойной submit активации, переименование через обычный редактор с тем же ключом карты;
- отмена факта закрывает неактивированное будущее, сохраняет активную цель; повторяемое дело не становится постоянным условием;
- регрессия прежних компактных виджетов: главное дело, быстрое добавление, план, ритм, таймер/подтверждение минут, покупка награды, ключевые действия/график/счастье/вечерний итог.

Фактические результаты и бекап — в текущем статусе. Физические iOS/Android, 1000 одновременно отрисованных узлов и одновременные финансовые операции вкладок не подтверждены. На холсте рисуется до 120 узлов выбранного фрагмента; остальные доступны через поиск и списки. Проверка file:// заблокирована политикой браузера среды (ERR_BLOCKED_BY_ADMINISTRATOR); проверки приложения шли через локальный HTTP. Локальные снимки: /workspace/visual-review/strategy-applied/.
