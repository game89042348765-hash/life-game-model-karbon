Концепция уже достаточно развита для перехода к реальному инструменту. Её ценность — связать существующие действия человека с выбранным будущим и показать следующий доступный шаг. Следующая работа должна связать эту модель с актуальным LifeGame и исправить логику карты. Ещё один автономный HTML с собственным списком задач проблему интеграции не решит.

## 2. Что сохраняем как основу

- При первом входе карта показывает уже существующие данные LifeGame. Не требуется повторно собирать жизнь вручную.
- «Я сейчас» — ориентир представления. Не отдельный денежный или календарный механизм.
- Блок может содержать одно задание без причины, смысла и цели. Нет обязательного психологического опросника.
- Связи свободные; обычная линия не запрещает действие. Обязательное условие задаётся явно.
- Допускаются параллельные направления и условия из другой сферы.
- Будущее видно заранее. Доступность будущего и его включение в реальную работу — разные операции.
- История сохраняется. Скрытие прошлого не удаляет факты и не отменяет выполненные условия.
- На телефоне основной вид должен отвечать: «Что для меня актуально и что можно сделать дальше?».
- Сохраняем текущий графит, готовые палитры и режим значков LifeGame. Не переносим жёстко заданную окраску макетов целиком.

## 5. Рекомендуемая модель инструмента

### Представление

1. Общий обзор: сферы и актуальные цели/направления, без сотен отдельных выполнений.
2. Выбор цели: локальный путь с обязательными предпосылками, включая другие сферы.
3. «Я сейчас» остаётся визуальным якорем. Видимые шаги раскладываются заново по оставшимся условиям; канонические ID и связи сохраняются.
4. Выполненные предпосылки представлены компактными отметками с доступом к фактам. «Показать путь» не разворачивает всю биографию.
5. «Что делать сейчас» показывает конкретные доступные действия из актуальных направлений. Ориентиры и цели могут быть рядом, но не выдаются за действия.
6. После выполнения сохраняется контекст и показывается следующий шаг. Без внезапных больших перемещений камеры и без оценки вероятности успеха по длине линии.

Расстояние на карте — навигационный приём, не обещание «до цели осталось ровно столько усилий». Не все жизненные условия известны заранее.

### Данные

Разделить три вещи:

- реальные сущности LifeGame: ссылки по типу и ID; имена, статусы и награды читаются из существующего state;
- будущие черновики, явные связи и условия: собственная версионированная модель стратегии;
- настройки вида: камера, фильтр, раскрытие и позиции; они не меняют выполнение или принадлежность задания.

Рекомендация: содержательные данные стратегии включать в общую резервную копию прогресса с совместимой нормализацией; частые движения камеры хранить отдельно как UI-настройку. Точный формат — проект следующего этапа. Не делать два независимых хранилища одинаковых задач.

Существующий единственный block.meaning отображается как существующий смысл. Дополнительные смыслы сначала могут быть элементами стратегии; расширять каноническое поле до массива без отдельной миграции не нужно.

Структурное «принадлежит» и пользовательские «связано / помогает / требуется» должны быть разными отношениями. Рисование линии не меняет task.goalId или блок незаметно. При архиве/замене импорта ссылка явно становится недоступной, а не указывает на случайный новый объект.

### Предлагаемые правила доступности

- Обычные и полезные линии ничего не блокируют.
- Для «Все» нужны все обязательные факты; для «Любое» достаточно одного. Дополнительные альтернативы не выдаются как обязательные первые шаги.
- Условие стало выполнено → будущая ветка доступна. Взять её в работу — отдельное явное действие, не автоматическое создание реального задания.
- Ранее существующее задание не блокируется новой линией стратегии.
- Для повторяемого дела показывать «выполнено сегодня», а не «выполнено навсегда». Серии, количества повторений и временные окна условий — отдельное решение.
- При отмене факта будущая неактивированная ветка пересчитывает доступность; уже активированные реальные дела не исчезают автоматически. Расхождение показывается пользователю. Это рекомендация для согласования.
- Смысл и причина — ориентиры/контекст; не делать их обязательными галочками выполнения.
- Новых выплат за открытие ветки не вводить.

## 6. Предлагаемая поэтапная реализация после обсуждения

### 2.1. Живая карта существующего приложения

Адаптер текущих данных, системный виджет-вход, общий обзор и локальный путь, поиск и переход к реальному объекту. Просмотр карты не пишет прогресс. Работа на собственных данных уже приносит пользу, даже до создания будущих веток.

На этом шаге не выводить бонусы/покупки/каждое календарное событие на основной холст автоматически. Сохранить их в приложении; возможность привязывать другие типы объектов добавить явно отдельным шагом. Это продуктовая рекомендация: прежняя концепция предлагала более широкий охват, поздние демо его сократили.

### 2.2. Будущие ветки и достоверный путь

Сохраняемые черновики, причины/дополнительные смыслы, типизированные связи, И/ИЛИ, объяснения закрытия, отмена редактирования стратегии, валидация импорта/экспорта. Компактная история с новой раскладкой видимого графа. Повторяемость не подменяется boolean.

### 2.3. Связь с ежедневным использованием

Явный перевод будущей цели/дела в реальные записи с просмотром последствий и защитой от дублей. Действия «На сегодня», «Открыть дело», «Начать подход» используют существующие механизмы. Если панель «Что делать сейчас» нужна вне карты, оформить её системным виджетом и связать с уже существующим «Шагом к цели», не дублируя независимый выбор следующего дела.

AI-предложения, призрачные альтернативы, сложные серии привычек и прогнозы усилий отложить до устойчивой основы. Сам инструмент полезен без них.

## 7. Решения, которые стоит согласовать перед кодом

1. Основное представление: общий обзор сфер → локальный путь; прошлое свёрнуто, «Я сейчас» визуальный якорь. Рекомендую этот вариант.
2. Условия: доступны «Все / Любое», открытие не создаёт дело; включение будущего в работу вручную. Определить, что делать после отмены условия уже активированной ветки.
3. Первая интеграция: реальные блоки/смыслы/цели/дела и вход через системный виджет; прочие сущности добавлять по необходимости, без нового обязательного нижнего пункта меню.
4. Для первой версии условий достаточно достигнутой цели и конкретного разового выполнения. Критерии привычек и будущая модель нескольких реальных смыслов согласуются отдельно.

Это предложения, а не уже принятые решения. По текущему поручению выполнен только анализ.

## 8. Приёмка рабочего инструмента

- Минимальная ветка «Гитара → 20 минут» работает без цели/смысла.
- Изменение обычного задания вне карты сразу отражается в стратегии с тем же ID.
- Карта правильно объясняет зависимость из другой сферы и не скрывает её при сворачивании соседней сферы.
- И/ИЛИ и ближайший шаг согласованы, выполненная альтернатива не требует выполнения второй.
- «Сегодня выполнено» у повторяемого дела не закрывает привычку навсегда.
- 30–50 выполненных шагов не удлиняют оставшийся путь; история доступна по запросу.
- Ошибка сохранения не показывает успешное применение; импорт валидируется полностью до записи.
- Старая копия прогресса открывается без стратегии, новая сохраняет её без потери прежних журналов.
- Включение будущего в работу не создаёт дубль при повторном нажатии.
- На узком телефоне ближайшее действие читается без поиска по миниатюрному графу.
- Производительность больших карт, две вкладки и реальные телефоны проверяются на соответствующих этапах; результаты этого разбора их не подтверждают.
