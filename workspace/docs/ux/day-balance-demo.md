# Посильный план и закрытие дня — отдельное демо

[Открыть демо](https://game89042348765-hash.github.io/life-game/demo/day-balance.html)

Два следующих системных виджета представлены вместе на вымышленных данных. Основной index.html, журнал времени, денежные правила и сохранения не менялись. В демо нет localStorage/API/AI; всё живёт в памяти страницы до перезагрузки или сброса.

## План

Бюджет на все сегодняшние дела допускает 0 минут. Оценки каждого дела необязательны; пустые оценки показываются как неизвестный объём, а не нулевой. Уже выполненные дела входят в исходную оценку всего плана. Записанное фактическое время показано отдельной демонстрационной строкой и не выводится из оценок или галочек.

Перегрузка — подсказка. Предложение облегчения берёт известные оценки незавершённых дел с конца списка, сохраняет главное и выполненное. Дела без оценки требуют ручного решения. Предпросмотр показывает список и остаток, включая ситуацию, когда главное/выполненное уже превышают бюджет. Применение отдельной кнопкой оставляет дела в Позже. Можно отменить последнее облегчение; дальнейшее редактирование плана завершает возможность этой отмены, чтобы не перезаписать новые решения.

## Вечер и следующий день

Оба текстовых поля необязательны. По оставшемуся делу можно выбрать завтра, позже, оставить в текущем плане или ничего не выбирать. Только сохранение итога применяет решения. Повторное сохранение обновляет решение по ID без повторной записи. Пропуск итога сохраняет текущие дела и черновик в памяти страницы.

Следующий день — симуляция. В него входят только явно выбранные для завтра дела; оставшиеся вчера показываются отдельной очередью, позже остаётся позже, выполненные разовые дела не возвращаются. Выбор главного начинается заново. Демонстрационный факт времени на новый день равен 0, а не вчерашним 25 минутам. Предыдущий сохранённый итог можно открыть в вечернем виджете. Хороший момент сохраняется только внутри примера и не пополняет настоящую коллекцию.

## Проверка пользователем

1. Поменять бюджет и оценки, оставить одно дело без оценки.
2. Открыть предложение облегчения, проверить состав до применения, применить и отменить.
3. Оставить главное с оценкой больше бюджета: увидеть честную перегрузку без запрета действий.
4. Вечером написать итог по желанию, разнести дела между завтра/позже/оставить, сохранить дважды.
5. Перейти к следующему дню, посмотреть очереди и прошлый итог.

Для основной версии ещё нужны согласованные поля хранения, совместимость JSON, интеграция с реальными дневными планами/разбором прошлого и проверка отмен/конфликтов/денежной истории. Этот прототип не заявляет, что такая интеграция уже выполнена.
