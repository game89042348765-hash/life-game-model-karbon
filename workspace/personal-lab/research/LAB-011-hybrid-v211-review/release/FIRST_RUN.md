# Первые передачи моделям

Ни одно из этих заданий ещё не отправлено и не выполнено. Это готовые плановые пакеты калибровки. Не нужно начинать исследование сразу на 10 000 строках: сначала проверяется качество входа и прохождение всех стадий.

## Вариант с одним оркестратором

Передайте весь ZIP выбранной модели и стартовое сообщение из START_HERE.md. Она создаёт рабочую папку и реестр, выдаёт задания и принимает возвращённые файлы. Пользователь выбирает, в каких внешних аккаунтах запускать исполнителей.

## Первые четыре задания поиска

| TASK-ID | Файл задания | Участок | Ориентир |
|---|---|---|---|
| CAL-SEARCH-01 | starter_tasks/CAL-SEARCH-01.json | Захват и календарное планирование: C05, C08 | 10–15 качественных находок |
| CAL-SEARCH-02 | starter_tasks/CAL-SEARCH-02.json | Нагрузка и возвращение после перерывов: C09, C12 | 10–15 |
| CAL-SEARCH-03 | starter_tasks/CAL-SEARCH-03.json | Игровой прогресс и экономики: C21, C22 | 10–15 |
| CAL-SEARCH-04 | starter_tasks/CAL-SEARCH-04.json | Контроль данных и восстановление: C28, C29 | 10–15 |

Это четыре запуска, при желании в разных моделях. Необходимости в четырёх разных платных сервисах нет. Совмещение и доступные инструменты фиксируют. Малое пересечение допустимо, так как проверяет обнаружение дублей.

Для каждого запуска оркестратор копирует соответствующий файл как TASK.json, назначает реального владельца и status=assigned в рабочем реестре. Передаёт комплект и текст:

> Выполни PROMPTS/01-SEARCH.md по приложенному TASK.json. Это калибровочный участок большого справочного исследования. Проверь реальные возможности веб-доступа. Сохраняй источники, находки и журнал по DATA_CONTRACT.md. Не ограничивайся известными приложениями и не выдумывай материалы ради количества. Верни ZIP с файлами, манифестом и ограничениями. Код и функции LifeGame для этого задания не нужны.

Если сервис не читает ZIP, используйте PASTE/01-SEARCH.txt и вставьте выбранный TASK.json отдельным блоком. Текстовый комплект содержит договорённости; исполняемый инструмент передаётся отдельно только тем, кому он нужен.

## После четырёх возвратов

1. Принять или вернуть на исправление каждый пакет по SYSTEM.md. Сохранить оригиналы.
2. Выдать normalize по PROMPTS/02-ANALYZE.md на все принятые находки. Затем analyze на все самостоятельные элементы. Это разные задания одного либо нескольких исполнителей.
3. Создать два новых контекста rate. Дать им одинаковые проанализированные карточки, источники и SCORING.md; чужие баллы не показывать.
4. Объединить полный снимок, проверить и сделать пробный расчёт. При 40–60 находках он закономерно не заполнит цель 100–300 — это проверка процесса, а не итоговый атлас.
5. Выдать независимую проверку по PROMPTS/04-AUDIT.md. Устранить ошибки формата, источников, дублей и якорей. Зафиксировать методику массовой волны.
6. Выдать тематические поиски по всем 32 категориям и пробелам. Принимать волнами, поддерживать глобальный индекс и не сокращать каталог до локальных победителей.

Не запускайте этап отбора вместо анализа всех принятых записей. Если одна модель не может прочитать весь снимок, передайте ей конкретный пакет с ID и сохраните очередь остальных. Общий расчёт читает файлы целиком; общий смысл проверяется распределённым анализом и аудитом.

## Что передавать на каждой стадии

Поиск: TASK + промт 01 + классификация + договор данных + правила поиска.

Анализ/оценка: TASK с режимом + промт 02 + полные назначенные записи и источники + глобальный индекс + договор + рубрика. Оценщику не передаются чужие оценки.

Отбор: TASK + промт 03 + весь снимок и хеши + RUN + рубрика + программа расчёта.

Аудит: TASK + промт 04 + индекс всего каталога, отбор, исключения и первичные материалы для фактической проверки.

Сопоставление с приложением: промт 06 + выпущенный атлас + проверенный срез приложения. Этот проход выполняется отдельно, когда будет нужен.
