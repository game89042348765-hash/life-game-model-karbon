# Следующий шаг — 40–60 реальных находок

Это рабочий комплект для первого содержательного прохода, не результат исследования. Исходники приложения для поиска не нужны. Не расходуйте ещё один круг на перепроектирование системы: сначала проверьте её на настоящих материалах.

1. Передайте этот ZIP модели-оркестратору со стартовым сообщением ниже. Она должна честно проверить веб-доступ и умение создавать файлы. Доступа к GitHub не требуется.
2. Используйте четыре готовых starter_tasks/CAL-SEARCH-01..04.json и FIRST_RUN.md: захват/календарь; нагрузка/возвращение; игровой прогресс/экономики; контроль данных/восстановление. Ориентир каждого — 10–15 подтверждённых находок. Назначайте реальных исполнителей в реестре, не объявляйте плановые задания выполненными.
3. На каждом возврате сохраняйте исходный пакет, источники, claims, журнал поиска и манифест. Не дописывайте находки ради количества, не выдавайте маркетинговое обещание за доказательство эффекта. Без доступа к странице — явный непроверенный статус.
4. Проведите весь принятый вход через нормализацию, глобальную проверку дублей, анализ, две независимые слепые оценки, расчёт и аудит. Не выбрасывайте необработанные записи ради локальных победителей. Оригиналы и версии сохраняются.
5. Для `shard` резерв общего промта считайте по **реально передаваемым** TASK/инструкциям/рубрике/таксономии и добавляйте запас в `--prompt-reserve-bytes`. По умолчанию резерв равен 0: это не означает, что инструкции бесплатны. Байты не равны токенам; дополнительно сверяйте фактический лимит выбранной модели. Сверхкрупные связки имеют отдельный статус, обычному исполнителю их не отправляют незаметно.
6. На 40–60 находках целевой атлас 100–300 закономерно не заполнится. `target_reached=false` не повод заполнять пробел выдумками. Проверьте качество происхождения, различимость единиц, ясность рубрики, время/стоимость этапов, сохранность и удобство ручной передачи.
7. Выпустите CALIBRATION-REPORT.md: что реально сделано, счётчики каждой стадии, ошибки/потери, спорные решения, ограничения источников, фактические затраты и узкие исправления. Только затем выбирайте массовую волну.

Сообщение оркестратору:

> Распакуй комплект LifeGame Atlas Hybrid 2.1.1+lab.1. Прочитай START_HERE.md, COORDINATOR-PATCH.md, CALIBRATION_START.md и FIRST_RUN.md. Техническая основа проверена; задача — калибровочный проход на 40–60 реальных находках, без перепроектирования архитектуры и массового сбора. Сначала проверь свои инструменты, создай реестр и подготовь автономные задания по четырём starter_tasks. Если тебе поручен поиск и доступен браузер — выполняй его с источниками и файлами. Если доступа нет — укажи ограничение и не сочиняй результат. Внешние аккаунты подключает пользователь; выданное задание не означает исполнение. Верни структурированные файлы, манифест и честный отчёт. Исходники LifeGame для этого поиска не нужны.
