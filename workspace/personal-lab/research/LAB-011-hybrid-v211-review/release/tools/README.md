# Локальные инструменты конвейера

## Уточнения рабочего выпуска LAB-011

`prepare-blind` публикует результат через атомарный hardlink в той же файловой системе. Если каталог не поддерживает жёсткие ссылки или запись запрещена, команда отказывается без создания конечного результата и удаляет staging. Выберите поддерживаемый локальный каталог; небезопасного прямого fallback нет. Реальная проверка выполнена на Linux; остальные ОС/файловые системы не объявляются проверенными.

Если даже одна навигационная строка не помещается в `--index-max-bytes`, `shard` явно отказывается без публикации выходной папки. Увеличьте бюджет индекса или уменьшите `--preview-chars`. Полные входные тексты остаются на месте.

Проверки: `python3 -B tools/verify_tools.py --report /новый/report.json` и `python3 -B tools/acceptance.py --out /новый/acceptance.json`. Это вымышленные технические сценарии, не интернет-исследование.


Нужен Python 3.10 или новее. Сторонние пакеты, интернет, API-ключи и оплата не нужны. Программа не открывает страницы и не вызывает модели. Она проверяет структуру/ссылки и применяет зафиксированную редакторскую формулу к уже подготовленным данным.

Запускайте из корня распакованного комплекта. Рабочие результаты храните в отдельной папке исследования. На Windows используйте доступную команду python вместо python3.

## Проверка комплекта

    python3 tools/atlas.py verify .

Это сверка файлов с манифестом, а не подтверждение авторства архива. Сам манифест доверяют только вместе с полученным исходным комплектом.

## Проверка технической реализации

    python3 tools/verify_tools.py

Проверки создают временные вымышленные данные, в том числе 10 000 элементов. Они проверяют программу, а не качество исследования. Запросы в сеть и браузер не используются. Для сохранения отчёта добавьте --report /путь/к/новому-отчёту.json.

## Проверка пакетов и снимка

    python3 tools/atlas.py validate /путь/к/поисковому-пакету
    python3 tools/atlas.py validate /путь/к/снимку --complete

Первый режим допускает незавершённую нормализацию. Второй требует судьбу каждой находки и взаимные связи raw_ids/merge_map. Оба проверяют существующие таблицы. Пустые таблицы не превращаются в выполненную работу; смотрите counts. Факты страниц, смысл дублей и независимость оценщиков не проверяются кодом.

Задания rate часто возвращают только ratings.jsonl: сначала объедините их с соответствующим полным входным снимком в новую папку, затем проверяйте связи. Отдельная таблица с внешними ID может закономерно не пройти автономную валидацию.

## Сборка нового снимка

    python3 tools/atlas.py merge --out /путь/к/release-0001 /путь/к/пакету-A /путь/к/пакету-B

Обрабатываются семь таблиц DATA_CONTRACT.md. Одинаковые строки одного ID объединяются технически. Разный смысл одинакового ID останавливает операцию. Семантическая дедупликация не выполняется. Исходные пакеты, поисковые журналы и отчёты остаются отдельно в accepted; MERGE.json сохраняет хеши объединённых JSONL, но не заменяет манифесты исходных пакетов.

Исправление существующей записи — явное решение и новый снимок с выбранной новой версией строки. Не передавайте одновременно старую и исправленную строку как будто это две равноправные записи. Утилита не выбирает последнюю молча. Выходная папка должна отсутствовать; существующий выпуск не перезаписывается.

## Расчёт

Скопируйте templates/RUN.json в RUN.json своей папки исследования, заполните реальные параметры, зафиксируйте их до массового отбора. Команда:

    python3 tools/atlas.py rank /путь/к/release-0001 --config /путь/к/RUN.json --out /путь/к/новому-выпуску

Вход должен пройти полную структурную проверку. Выход: quality-ranked.csv, atlas-selection.json, audit.json, ATLAS-DRAFT.md. CSV сохраняет технический order и одинаковый score_rank при одинаковом Q. audit.json содержит хеши входных JSONL, классификации и программы, фактически использованные параметры, недопуски, пробелы и шесть объявленных сценариев чувствительности.

Результат всегда черновик до содержательной приёмки. target_reached=false означает, что кандидатов выше порога меньше цели; программа не добирает места слабыми данными. Неизвестные оценки не заменяются нулём. Расхождения от двух пунктов требуют отдельного решения.

Программа поддерживает редакцию 1.0. При смене структуры/рубрик/категорий обновите программу и проверки новой версией; один новый номер в RUN.json не обеспечивает совместимость. Профили чувствительности зафиксированы в SCORING.md и коде.

## Только демонстрация

    python3 tools/atlas.py validate examples/demo --complete
    python3 tools/atlas.py rank examples/demo --config examples/RUN.demo.json --out /путь/к/новому-demo

Вымышленные записи помечены synthetic=true. Обычный research-расчёт откажется их включать. Демонстрация выдаёт synthetic_demo_not_research. Даже если удалить метку, вымышленные источники не становятся реальными: окончательная проверка остаётся содержательной.

## Целостность выходов

    python3 tools/atlas.py seal /путь/к/новому-выпуску --manifest FILES.json
    python3 tools/atlas.py verify /путь/к/новому-выпуску --manifest FILES.json

seal создаёт перечень файлов с SHA-256 и отказывается заменить существующий манифест. RESULT_MANIFEST.json задания дополнительно требует метаданные задачи: их заполняют по шаблону, используя список файлов из FILES.json. До seal закончите запись файлов. Изменения после фиксации требуют новой версии, не исправления старой квитанции.

## Что программа намеренно оставляет людям и моделям

Поиск, проверку фактического содержания, семантическое объединение, анализ причинной цепочки, независимые оценки, разбор спорных решений, редактирование ATLAS.md и сопоставление с приложением. Ни синтаксис, ни контрольная сумма не доказывают полезность механизма.
