# Повторение анализа LAB-015

В `R1`, `R2`, `R3` лежат результаты трёх завершённых сценариев: настоящие Playwright traces, PNG, JSON наблюдателя, журнал UI-действий и результат. Первичные профили участников не использовались. Каталоги `*-attempt*` сохраняют предыдущие попытки со сбоями автоматизации; объяснения — в `ATTEMPTS.json`. Они не являются доказательствами дефектов приложения.

`reproduce.py` использует новый изолированный Chromium context для каждого сценария, виртуальные часы Europe/Moscow до загрузки и только обычные UI-действия. Все запросы вне указанного origin отклоняются, service workers отключены в этих изолированных сценариях. Это не повторная проверка офлайна. `evaluate` только читает DOM/геометрию и localStorage для наблюдателя; записи в хранилище и вызовов внутренних функций нет.

Требуются Python с Playwright и Chromium. В исходной среде использован `/usr/bin/chromium`; при иной установке измените только `executable_path` в копии скрипта для своего компьютера. Не запускайте поверх каталога с доказательствами: скрипт откажется его перезаписывать.

Для другого аккаунта или компьютера сначала распакуйте именно приложенный `source-kit.zip` в отдельный каталог. Его SHA-256 должен быть `2ef8f218ac75cf963c6e1f431509f1c75f04f51b6e91dc6dfad4ba9ffe5d727f`. Внутри находится каталог `LifeGame-LAB-014-Pilot/public`; документы старых результатов для повторения не нужны.

Например, из каталога распаковки запустите собственный локальный сервер:

```sh
python -m http.server 9035 --bind 127.0.0.1 --directory LifeGame-LAB-014-Pilot/public
```

Из каталога этого отчёта в другом терминале:

```sh
python reproductions/reproduce.py --url http://127.0.0.1:9035/personal-lab/ --output-dir reproductions/my-rerun R1 R2 R3
```

Порт `9035` — пример; `42367` в записанных артефактах — адрес только исходного стенда. Укажите фактический свободный порт своего сервера. Без `--output-dir` создаётся новый каталог `reproductions/rerun-<UTC>`. Можно передать только `R1`, `R2` или `R3`; без списка выполняются все три. Код приложения и первичный опыт не изменяются.

Условия сценариев:

- R1: 390×844, ежедневное чтение; 5 минут 16 ноября и 8 минут 17 ноября без отметок. Проверить 13 сохранённых минут и 0 отметок в Базовом.
- R2: 1100×844, простой разовый макет со сроком в названии. Проверить форму без поля даты и сохранённое `sched.date: null` после перезагрузки.
- R3: 375×844, разовый скетч 16 ноября с 3 минутами и отметкой. После подтверждённого сохранения перейти на 21 ноября, найти действие через Полный → Поиск, изменить на субботы, записать 4 минуты и отметить. Проверить сохранение фактов двух циклов, 7 минут и положение кнопки сохранения ниже исходного экрана формы.

Просмотреть настоящий trace можно установленной командой Playwright `show-trace` с относительным путём, например `reproductions/R3/trace.zip`. `audit_primary.py` отдельно повторяет сверку неизменности первичных файлов, журналов и состояний, если полный каталог опыта находится над `reproductions`. Он не запускает UI и не читает исходный код или старые находки.
