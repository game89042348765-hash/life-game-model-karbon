# После пилота: 16 цифровых пользователей × 30 дат

Обновление LAB-005, 12 ноября2026: native-восстановление внедрено и прошло9групп технической приёмки. R1/R2 исправлены, требуется явная сверка неопределённого действия. [Подробности](../LAB-005-resume/IMPLEMENTATION.md). Предыдущая полная редакция этого плана — в ../LAB-005-resume/history/. Это ещё не повторный AI-пилот и не запуск16×30.

Это план следующего прогона, не его результаты. Предел проекта 12–20; подготовлено 16 разных профилей и 480 календарных строк. `world.month.json` воспроизводимо генерируется `make_world.py` с seed `2026111102`.

## Порядок запуска

1. Сначала завершить пилот, сохранить исходные доказательства, провести независимый разбор и проверить ошибки транспорта. Исправление приложения — отдельное поручение, результаты baseline сохраняются.
2. Перед большим опытом дополнить мир конкретными событиями по целям пользователей: что реально сделано вне приложения, даты встреч/повторов, изменившиеся сроки и частичные усилия. Сейчас месячная конфигурация содержит профили, даты и жизненные контексты; не считать её измеренным поведением или полностью детализированной биографией.
3. Создать новый run-dir, копию мира и точного приложения с хешами. Старые профили пилота не переиспользовать для нового первого запуска. Если вместо нового старта продолжаем пилот до 30 дней, первые семь дней мира должны дословно соответствовать пилоту; текущий world.month — отдельный новый опыт.
4. Назначить отдельные чистые контексты AI-модели каждому профилю. Контекст разработчика/аналитика не годится для слепого пользователя. Очередь — до трёх активных участников. Номера actor и данные всегда независимы, модельную память не смешивать.
5. Один агент решает по своему brief, своей памяти и текущему экрану. Мир не подменяется списком обязательных функций. Нельзя выполнять одни и те же клики за всех 16 участников.
6. После каждого дня фиксировать opened/no_use и завершённую сессию, не пропускать даты без записи. После каждого этапа проверять profiles/state/traces. Если достигнут лимит или сломан инструмент, сохранять статус blocked/unrun, а не дописывать успешный месяц.
7. Независимый аналитик воспроизводит важные наблюдения, проверяет их другим агентом/семейством модели по возможности. Реплики модели и одинаковые решения разных контекстов не становятся статистикой настоящих людей.

Команды транспорта после подготовки мира и независимых AI-исполнителей:

```sh
python3 personal-lab/research/LAB-002-digital-month/driver.py serve \
  --world personal-lab/research/LAB-002-digital-month/world.month.json \
  --run-dir personal-lab/verification/month-main-001 --port 8052
```

HTTP-сервер приложения должен работать отдельно на 8041. Дальше оркестратор выдаёт исполнителям PROMPT-USER и их actor, они используют brief/session/act/end/skip. Наличие запущенного driver само по себе не означает, что AI-пользователи подключены.

## Что нужно до надёжного длинного запуска

- Восстановление и освобождение завершённых browser context реализованы в LAB-005. Использовать новую схему2 с --resume; старые prototype-каталоги не мигрировать молча. После технической приёмки ещё проверить целый пользовательский маршрут повторным AI-пилотом. Не запускать месяц сразу по одному факту прохождения технических тестов.
- Для покрытия импорта добавить явный UI file-upload с искусственными файлами; для многовкладочности — управление вкладками одной персоны. Их отсутствие в транспорте не является отсутствием функций приложения.
- Native JavaScript dialogs в текущем транспорте автоматически отклоняются и помечаются в журнале. Для исследования таких путей нужен явный ответ самого участника; нельзя приписывать автоматический отказ его намерению.
- Записывать версии браузера/Playwright/Python, фактическую модель и настройки, если сервис их сообщает, время ожидания отдельно от действия. Сохранять короткие недельные сводки, а не весь диалог каждому следующему решению.
- Найденное после пилота раскрытие текста под фиксированной панелью исправлено в текущем driver; шесть узких проверок наблюдения прошли. Перед основным опытом проверить этот вариант на небольшом живом маршруте. Доступные подписи/варианты select всё ещё являются DOM-помощью, а не чисто визуальным вводом.
- Базовые вероятности возврата/ошибок в профилях — пока заданные параметры роли, не калиброванная модель поведения. Проверить чувствительность к бюджету действий и разным семействам моделей; не пытаться силой получить заданную долю отказов.

Это ограничения стенда/методики, не список исправлений продукта. Перед массовым запуском достаточно закончить нужные для выбранного покрытия пункты; не превращать пилот в разработку универсальной платформы.

## Стоимость

Первое приближение по фактам пилота: число операций и наблюдений на реально открытый день, затем отдельная надбавка за первые запуски, долгие накопленные списки, перепроверку ошибок и анализ. При новых целевых профилях структура действий может существенно измениться; простой линейный перенос не является прогнозом.

Внешние модели пользователя можно подключать как исполнителей в их средах с браузерными инструментами и точным срезом приложения. Доступность больших чат-лимитов сама по себе не даёт API или браузерного инструмента. Если есть только чат, передавать ему проектирование и анализ, а не объявлять самостоятельные UI-сессии выполненными. Не запрашивать платные ключи ради запуска по умолчанию.
