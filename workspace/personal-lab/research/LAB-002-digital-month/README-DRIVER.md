# Стенд цифровых пользователей: native Playwright и восстановление

Актуально после LAB-005, 12 ноября 2026. Только лабораторная инфраструктура: код приложения, данные настоящих пользователей и основная Personal не изменены. Историческая версия этой инструкции сохранена в ../LAB-005-resume/history/.

## Что работает

Стандартный Playwright/Chromium, отдельный persistent profile на actor, виртуальные даты до загрузки приложения, видимые DOM-элементы и PNG, настоящие UI-действия, checkpoint и журнал. Решения по-прежнему принимает отдельный AI-пользователь; driver не содержит модели/API. Selenium/CDP-fallback и обходов ограничений среды нет.

## Запуск

Нужны Linux, Python, Python Playwright и Chromium по /usr/bin/chromium (иной путь задаётся --chromium). Из корня checkout запустите HTTP-сервер приложения в отдельной сессии:

```sh
python3 -m http.server 8041 --bind 127.0.0.1
```

Если порт занят, проверьте существующий сервер; не завершайте чужие процессы. Для нового опыта выберите ещё не использованный run-dir:

```sh
python3 personal-lab/research/LAB-002-digital-month/driver.py serve --world personal-lab/research/LAB-002-digital-month/world.pilot.json --run-dir personal-lab/verification/pilot-new-001 --port 8052
```

Chromium запускается только при первом входе конкретного пользователя. День без UI не запускает браузер. Приложение должно обслуживаться по app_url из мира; по умолчанию это http://127.0.0.1:8041/personal-lab/. --app-dir задаёт локальные файлы для проверки версии, --profiles-dir — отдельный каталог профилей.

Клиент:

```sh
python3 personal-lab/research/LAB-002-digital-month/driver.py request '{"op":"brief","actor":"P01","day":1}'
```

Поддерживаются brief, session, skip, observe, act, scroll, end, release, status, audit, finish. Клиент по умолчанию обращается к8052; другой порт задаётся request --port. Сервер доступен только через loopback; роли actor/координатор разделяются организационно, это не сервис авторизации для недоверенных клиентов.

## Продолжение после остановки

```sh
python3 personal-lab/research/LAB-002-digital-month/driver.py serve --world personal-lab/research/LAB-002-digital-month/world.pilot.json --run-dir personal-lab/verification/pilot-new-001 --port 8052 --resume
```

Восстанавливаются закрытые/пропущенные даты, собственная память, расход бюджета, виртуальное время, счётчик наблюдений и активная сессия. Канонический журнал — events.jsonl, checkpoint содержит позицию в нём. Проигрывается только хвост после checkpoint. Полная запись no_use и память входят в долговечное событие, поэтому не пропадают при остановке перед checkpoint.

Мир, приложение (включая шрифты/иконки) и версия driver должны совпадать с записанными. Несовпадение отклоняется без переписывания исследовательских данных. Файлы блокировки остаются на стабильном inode; активный конкурентный запуск отклоняется. При штатном закрытии дня browser context освобождается, профиль остаётся на диске.

Новая схема checkpoint — **2**. Прототипные запуски без этой схемы и входящий кандидат со схемой1 не мигрируются молча. Сохраняйте их как исторические доказательства; новый опыт запускайте в новом каталоге. Исходный LAB-002 остаётся неизменным и проверяется отдельным evidence/verify.py.

## Неопределённое действие

После сбоя между UI-действием и подтверждением оно не повторяется автоматически. Новый observe показывает текущий экран и reconcile_required; несохранённый DOM-черновик не объявляется восстановленным. **Получение скриншота не снимает неопределённость.** После собственной сверки координатор/участник явно подтверждает решение продолжить без автоповтора:

```json
{"op":"reconcile","actor":"P01","observation_id":"АКТУАЛЬНЫЙ_ID","note":"На экране вижу сохранённое дело; отправку не повторяю"}
```

В истории остаётся unknown_not_retried. Это не автоматическое доказательство успеха прежнего действия. Если результат непонятен, остановите маршрут и зафиксируйте затруднение. До сверки act/scroll/end блокируются; бюджет уже потраченного действия не обнуляется. То же правило применяется к ошибке получения наблюдения после реального нажатия без завершения процесса.

## Обычный пользовательский цикл

brief сообщает жизненный контекст и только собственную память; до открытия UI можно выбрать skip. session открывает текущую дату. observe возвращает актуальный observation_id, видимые элементы eN, текст и screenshot. Примеры:

```json
{"op":"session","actor":"P01","day":1}
{"op":"act","actor":"P01","observation_id":"АКТУАЛЬНЫЙ_ID","element":"e1","action":"click","intent":"Открыть выбранное"}
{"op":"act","actor":"P01","observation_id":"АКТУАЛЬНЫЙ_ID","element":"e2","action":"fill","value":"Погулять","intent":"Записать дело"}
{"op":"scroll","actor":"P01","observation_id":"АКТУАЛЬНЫЙ_ID","dy":400,"intent":"Посмотреть ниже"}
{"op":"end","actor":"P01","outcome":"Дело записано","memory":"Свой результат и следующий шаг","frictions":[]}
```

select.value — видимое название варианта, check.value — boolean. Старые observation_id отвергаются. Лимит операций задан в мире, не скрывается автопилотом. Интерфейс пользователя DOM-assisted, не эквивалент физическому взгляду человека. Никакие __LG/записи в хранилище для создания данных не используются.

## Завершение, чтение и артефакты

finish — явное решение координатора, допустимое после закрытия активных сессий. Оно не дорисовывает оставшиеся даты: unrun остаются в сводке. Остановка daemon сама по себе не делает active-сессию completed и не помечает опыт finished.

```sh
python3 personal-lab/research/LAB-002-digital-month/driver.py serve --world personal-lab/research/LAB-002-digital-month/world.pilot.json --run-dir personal-lab/verification/pilot-new-001 --resume --read-only --port 8052
```

Read-only не запускает браузер и не переписывает журнал/checkpoint/summary; это чтение поддерживаемого формата на том же мире и приложении. Законченный опыт не открывается для мутаций. Снимок сводки восстанавливается из checkpoint и хвоста, а не берётся вслепую из устаревшего summary.

Старые события/PNG/traces не затираются. Продолжения имеют отдельные events.resume-NNN.jsonl и trace-resume-NN.zip. Реально сохранившиеся фрагменты прерывания отмечены отдельно; отсутствующая исходная трасса не подменяется копией продолжения. Эти файлы не считаются полным восстановлением прежней записи браузера.

Некорректная JSON-строка или нарушенная последовательность в каноническом журнале вызывают безопасный отказ. Скрипт не пропускает повреждённые строки и не ремонтирует данные молча. Браузерные часы не меняют время ОС; backend/cron у приложения нет. Импорт файлов, управление вкладками и native dialogs не расширялись: диалоги пока автоматически отклоняются с записью ограничения.
