## Что отправить модели

Передайте весь ZIP **координатору с исполнением Python/Chromium и возможностью создать три чистых контекста участников**. Вставьте текст PROMPT-RUNNER.md. Координатор передаёт участнику только participants/P01.md, P02.md или P03.md, затем его brief, собственные наблюдения и PNG. Разделять три роли абзацами одного диалога недостаточно. Полный ZIP участникам не передаётся. Аналитик получает отдельный чистый контекст после опыта.

Если модель умеет только читать/рассуждать, она должна вернуть конкретный `blocked`, а не выдуманный прогон. Для моделей в разных сервисах предусмотрен ручной обмен JSON/PNG через координатора; localhost разных машин не общий. Этот способ требует много ручных передач, поэтому предпочтительны отдельные контексты в одной среде с браузером.

## Быстрый запуск

Проверенная платформа: Linux, Python 3.10+, Node, Playwright и Chromium. Архив не содержит интерпретатор/браузер. Установка Python-зависимости, если её нет: `python3 -m pip install -r requirements.txt`. Установка браузера/системных пакетов — по правилам среды; его путь передаётся через --chromium. Платные API не используются.

Из распакованной папки:

```sh
python3 transport/bundle.py verify
python3 transport/bundle.py preflight --chromium /usr/bin/chromium
```

Терминал 1 — сервер приложения:

```sh
python3 -m http.server 8041 --bind 127.0.0.1 --directory public
```

Терминал 2 — транспорт, отдельный новый каталог опыта:

```sh
python3 transport/pilot_driver.py serve --world world.pilot.json --run-dir runs/pilot-001 --port 8052 --chromium /usr/bin/chromium
```

Клиент в той же среде:

```sh
python3 transport/pilot_driver.py request '{"op":"brief","actor":"P01","day":1}'
```

Приложение: http://127.0.0.1:8041/personal-lab/ в браузере **той же среды**. Эта ссылка не является общедоступной публикацией. Занятый порт сначала диагностировать; чужие процессы не завершать. Транспорт перед запуском сверяет все отдаваемые ресурсы с архивом, чтобы случайно не проверить другой сервер.

## Порядок работы

1. Заполнить копию execution-provenance.template.json в `runs/pilot-001/execution-provenance.json`: реальные модели/контексты/возможности; неизвестные значения оставить unknown. Сначала запустить транспорт, затем создавать файл внутри run-dir.
2. Выполнять даты 1–7 по порядку для каждой персоны. Всего 21 дата: 17 допускают вход, 4 недоступны. Вход в доступный день выбирает сама персона до session. Все даты должны получить настоящий статус; оставшиеся не дорисовываются.
3. При остановке возобновлять ту же команду с `--resume`, сохраняя runs/profiles и неизменный комплект. `reconcile_required` требует явной сверки. Не пересылать чужой опыт и будущие события.
4. Закрыть активные сессии. Координатор выполняет `{"op":"finish"}`. Finish сам по себе не означает, что учтены все даты. После завершения читать через `--resume --read-only`; обычный resume не открывает законченный опыт для записи.
5. `python3 transport/analyze.py --run-dir runs/pilot-001` создаёт FACTS.json. Отдельный аналитик проверяет настоящие артефакты и воспроизводит проблемы в свежем каталоге, сохраняя исходный опыт. REPORT-TEMPLATE.md задаёт отчёт.
6. Сохранить UX-REPORT.md, FINDINGS.json и фактические решения участников в run-dir, затем собрать ответ:

```sh
python3 transport/bundle.py collect --run-dir runs/pilot-001 --output LAB-014-results.zip
```

Вернуть results ZIP и короткое сообщение: завершён/частично/блокировка, учтено N/21, реальные модели/контексты, главные находки с доказательствами. Исходные браузерные profiles остаются в среде исполнителя для продолжения и не входят в ответ по умолчанию; переносимый браузерный сеанс этим ZIP не обещается.

[Методика и ограничения](METHOD.md). [Короткая ручная приёмка](MANUAL-ACCEPTANCE.md) проводится отдельно от слепых участников. `python3 transport/smoke.py` проверяет технику комплекта на временных данных; это отдельный smoke, а не выполнение AI-пилота.
