# Контракт опыта LAB-014

Цель — найти реальные затруднения повседневного использования нового варианта, проверить сохранение результата и возвращение после пропусков. Единица — персона-дата, не тест функции. 3 персоны × 7 дат 16–22 ноября 2026, Europe/Moscow. Жизненные события заданы заранее, клики не предписаны. Данные вымышленные. Это DOM-assisted AI-исследование с PNG, не репрезентативная выборка людей.

## Независимость и заморозка

- Координатор видит мир/код, но не выбирает клики вместо участника и не чинит ему маршрут. Каждая персона — отдельный чистый контекст модели с собственным профилем и памятью до 600 знаков. Контекст сохраняется между днями либо восстанавливается только из собственной истории. Модель/семейство/настройки записываются при доступности, иначе unknown.
- Участник видит только свою карточку, текущий brief, свои UI-наблюдения и PNG. Старые находки, устройство хранения, инструкции ручной приёмки, чужие и будущие даты скрыты. Разные контексты одной модели допустимы; это не разные семейства. Один диалог с тремя масками не выполняет контракт независимости.
- У продукта нет регистрации и backend. Независимость данных обеспечена отдельными persistent Chromium profiles P01/P02/P03, собственными localStorage, service worker и историей. Это не вымышленные облачные аккаунты. Копия приложения в public/personal-lab побайтово равна выбранному эксперименту; остальные версии не включены.
- Приложение не меняется внутри опыта. MANIFEST проверяет весь комплект, транспорт фиксирует runtime, включая flex-model.js/flex-ui.js; версия адаптера сохраняется отдельно. Любое исправление — отдельный срез/опыт с сохранением прежних артефактов.

## Время, входы и действия

Браузерные часы устанавливаются до загрузки страницы. День без входа не запускает UI/обработку; при возвращении приложение само обрабатывает накопленный интервал. ОС не переводится, backend/cron отсутствуют. Ускоренные даты не воспроизводят месяцы человеческой усталости или мотивации. В опыте есть конкретные даты встречи, перенос, частичное усилие, завершение проекта и один предусмотренный офлайн-вход. Первое посещение/кэш должны реально состояться до офлайна; неудача установки/сети классифицируется отдельно.

`decision_policy=agent_choice`. Числовые вероятности возвращения и случайная генерация ошибок не используются. Доступность — внешнее ограничение; в остальные дни вход выбирает персона. Бюджет — потолок click/fill/select/check/scroll, всего максимум **368** операций по миру, не число обязательных действий. Observe/brief и рассуждение модели расходуются отдельно. Исчерпание бюджета фиксируется как экспериментальный предел; потерю цели из-за него не объявлять багом продукта. Не добавлять тайные макросы или скрытые API-действия.

При неизвестном результате нажатия наблюдать заново и использовать reconcile. Предыдущее действие автоматически не повторяется. Блокировка транспорта, недоступный элемент, отсутствие экрана или смешение данных приостанавливают затронутый маршрут. Если независимые контексты/браузер/просмотр PNG недоступны, вернуть конкретный blocked или частичный статус; текстовая имитация не заменяет опыт.

## Доказательства и анализ

Журнал: реальные и виртуальные времена, намерение, операция, длительность транспорта, before/after PNG, observation_id, ошибки. На закрытом входе — trace, observer-state, собственная память. `completed` означает закрытую сессию, а не успешную цель. Дни `no_use/unavailable`, `no_use/actor_choice`, active, unrun и причины блокировок показываются отдельно.

Независимый аналитик получает реальные журналы и заявления участников. Сначала проверяет полноту/схему/непрерывность/изоляцию, затем цепочку «намерение → экран → действие → результат → сохранённое состояние». Читает факты до гипотез о причине. Повторяет предполагаемый технический дефект на свежих данных и сохраняет отдельное воспроизведение. Отделяет техническую ошибку, наблюдавшееся UX-затруднение, гипотезу AI, ограничение транспорта и известную границу продукта. Серьёзность обосновывает ущербом и восстановимостью, уверенность — качеством доказательств. Количество агентов не переводит в долю населения.

FACTS.json — только технические подсчёты и валидация реальных сохранений. Его успешность не доказывает соответствие намерению, независимость модели или удобство. Для полного пилота нужны 21 учтённая дата, доказательства всех входов, реальные отдельные контексты и независимый анализ. Завершённый с unrun опыт остаётся частичным. Вопросы, которые ни одна персона естественно не затронула, обозначаются «не проверено».

Ограничения транспорта: native диалоги автоматически отклоняются с записью, нет загрузки файла через UI/управления вкладками участником; нельзя делать вывод об этих функциях по данному опыту. Длительность нажатия не является временем человеческого выполнения задачи. Нет физического Safari/iPhone, синхронизации устройств, реальной доставки push при закрытом браузере и доказанного retention.

## Затраты и дальнейшее решение

Сохранить фактические операции/наблюдения/объём артефактов/время, модельные токены и цену при доступности, отдельно ручные передачи. Не обещать стоимость без тарифа. Три участника могут идти очередью, одна независимая модель может обслуживать разные чистые контексты. Платных API/внешних действий по умолчанию нет.

Выход — 1–3 приоритетных исправления с воспроизведением или явный вывод, что данных мало. Основной продукт не менять в этом задании. Сравнение с прежним Personal-пилотом качественное: вариант/персоны/условия изменены, причинный A/B-эффект не установлен. Месяц 12–20 пользователей обсуждается после этого пилота и ручной приёмки; текущий недельный комплект не объявляется готовым месячным миром.
